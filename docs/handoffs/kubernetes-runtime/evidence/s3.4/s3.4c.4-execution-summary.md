`inv-a86gc90t3r` 在六个真实 Cube Pod 上验证 BestEffort、Burstable、Guaranteed、

| 场景 | Guest 目标容器 readback | Host kubelet parent | Cube static leaf |
|---|---|---|---|
| BestEffort V1 | `cpu.max=max`、weight=1、memory=max、swap=0、oom.group=1 | `max/weight1/max` | `125000/536870912/512/1` |

| 2-vCPU/1GiB V5/V8 | resize app 初值=`30000/weight40/192Mi` | `55000/weight22/469762048` | `225000/1342177280/512/1` |

Host 逐对象审计 `inv-b86gd40042`、`inv-b86gfd0fqf` 证明六个 server/VMM 的 parent、
leaf、scope、WAL 和 RuntimeResource owner 对应唯一 Pod；leaf 内精确 server 进程以及所有
VMM/辅助线程，`pids.max=512`、`memory.oom.group=1`，unit active、WAL committed、VM/TAP
allocated。Cube 没有写 kubelet parent。

冻结表 V4 的 parent weight `38` 是换算笔误。Kubernetes v1.36.4 实际 CRI shares 加
RuntimeClass overhead 经 systemd cgroup v2 整数换算后为 `37`；该字段归 kubelet 所有，
Cube 只读。本页和设计页勘误以云端 kubelet readback `37` 为准，不改变 Cube controller
实现或其验收边界。Pod-level app 没有 container-level resources 时，Guest 收到并执行
Pod-level `700m/384Mi`，这是 v1.36.4 实际行为。

## 压力、隔离和动态更新

- Host CPU：`inv-a86ghggi40` 把受控 helper 放入 BestEffort leaf；`nr_throttled`
  `1→122`、`throttled_usec 2871→83307960`，同 Pod HTTP 保持可用。
- Host PIDs：`inv-a86ghi0ck0` 在 V2 leaf fork 487 个子进程后得到预期 `EAGAIN`，
  `pids.events max 0→1`，回收后 `pids.current=24`，HTTP 保持可用。
- Host memory OOM：`inv-686gpqgukm` 的受控 allocator 进入 V1 leaf 后被 SIGKILL；
  `memory.events max 0→39`、`oom 0→1`、`oom_kill 0→3`、`oom_group_kill 0→1`。
  `inv-986gprg80w` 同时对其余五个 Pod 发出 100 次 HTTP，请求失败为零，跨两个节点的
  sibling 身份全部稳定。
- Guest 定向 OOM：旧 Agent 的首次实测 `inv-b86gm40d0e` 暴露
  `cgroup.events populated=0` 早于 `memory.events` 被处理，Kubernetes 只能看到
  `Error/137`。`90026f59` 改为注册前后读取 `oom_kill` 基线，并在每次 cgroup event 上优先
  比较 OOM counter，再判断退出。最终 `inv-386h170wa5` 得到精确
  `reason=OOMKilled, exit=137`；Pod 内 survivor、同节点 survivor、跨节点 survivor 身份稳定，
  HTTP `3/3`。
- resize under pressure：`inv-a86gjv0v05` 在持续 CPU 压力中把 app 从
  `300m/192Mi` 更新为 `450m/240Mi`；Pod UID/IP/container ID 不变、restartCount=0，Guest
  readback `45000/weight54/240Mi`，`nr_throttled 710→954`。`inv-986gkm0tjk` 证明 kubelet
  parent 更新为 `70000/weight28/520093696`，Cube leaf 仍为
  `225000/1342177280`，WAL 仍为创建期静态值。
- 整个 CPU/PIDs 压力期间，`inv-v86ghig8c8` 对五个 sibling/两个节点做 90 次 HTTP，
  失败为零。
