## 本轮发现并修复的阻断问题

`inv-a86bebg110` 首次 sibling/PID 诱饵运行发现 PVM 6.6 内核对已经退出且 `/proc/<pid>` 已消失的
bootstrap helper 调用 `pidfd_open` 返回 `EINVAL`，而实现只把 `ESRCH` 视为进程消失，导致 watchdog
扫描中止。`2a3927a1` 增加保守兼容：仅当 errno 为 `EINVAL` 且 `try_exists(/proc/<pid>)` 明确返回
false 时判定 `Gone`；`/proc` 仍存在或查询不确定时继续 fail closed。纯函数 errno/presence 矩阵与
missing-PID 测试已加入。

随后 reviewer 找到三个会阻断故障收敛的锁序/时序缺口：scanner 发布 failure/cleanup 前等待
`operation.lock`，会被卡死 provider RPC 阻塞；Host placement 在 systemd/cgroupfs 外部副作用期间
长持 `record.lock`，scanner 无法 durable revoke；cleanup 在 signal server 前等待 operation
barrier，形成循环等待。`90edf7bf` 改为 scanner 先在 `record.lock` 下 fence，Host INTENT 前后短持
record lock且提交前复核 epoch/revoke/identity/target，cleanup 则按 durable handoff→精确
signal/wait→operation barrier→queue ready 收敛。同时 process identity read 失败只在
`try_exists(/proc/<pid>)=false` 时判定 Gone，其他错误保持 fail closed。
