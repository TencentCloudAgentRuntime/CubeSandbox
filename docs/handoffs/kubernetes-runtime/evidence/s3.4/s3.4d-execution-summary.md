# S3.4d 压力回归与支持矩阵执行摘要

日期：2026-09-03

实现基线：`10b7af56`（包含 `7526fc29`、`5b4b15dc`、`011a05fa`、`d40d9e07`、
`4066b17d`、`6662316e`、`2dcf26b9`）

环境：Kubernetes `v1.36.4`、containerd `2.3.4`、Linux `6.6+`、两个 PVM Worker、
`RuntimeClass/cube`

## 结论

状态：`DONE`。同一 reviewer 已对 `10b7af56` 及本摘要终审，明确返回
`APPROVE S3.4 DONE`，P0/P1/P2 阻断项均为 0。

S3.4d 的资源主路径已达到候选验收状态：默认 VM 内存下限、启动即 Guest OOM、
Kubernetes/直接 CRI 的极端内存下调保护、普通 in-place resize、containerd 在线重启、
QoS/多容器/init/sidecar/Pod-level 资源读回、双层 Host/Guest cgroup 和删除收敛均通过。
S3.4b 已通过 swap、PIDs、hugepage；本轮补齐 Host-backed emptyDir 的
ephemeral-storage 超限计量/驱逐证据，没有把 Guest 临时 rootfs upper 扩大为已支持。

仍有一个已知 P1 限制：同一容器执行长时间 `exec` 并同时 resize 时，Agent 内部 container
操作仍可能串行化，第一次 Update/探针可能在 8～10 秒超时；kubelet 重试后 resize 能最终
收敛，但 exec 客户端可能被 Pod 删除终止。该组合不计入首版已支持能力，登记为
`K8S-OQ-022`，后续在 S5.4 做 per-container operation actor/锁粒度整改。它不影响普通
create/start/stop/exec、无并发 exec 的 resize 或本次 Kubernetes E2E 基础验收。

另有一个非阻断快速取消边界：12 个 Sandbox 在创建 2 秒后同时删除时，systemd scope 收集
偶尔超过 Shim 的 1 秒有界重读，kubelet 会记录瞬时 `FailedKillPod` 后自动重试成功。最终
Pod/namespace 删除、两个 Worker exact-zero。该边界登记为 `K8S-OQ-023`，转 S5.4，不把
“极端快速取消零告警”列入首版支持声明。

## 实现与制品

- `7526fc29`：为 Agent exec admission 增加超时和清理；VM memory floor 固定为 256 MiB，
  managed Pod 的 Host leaf 至少为 512 MiB，低于下限的显式 VM 注解明确拒绝。
- `5b4b15dc`：managed memory downsize 未携带 CRI `checkBeforeUpdate` 时默认执行写前用量
  检查；显式 false 仍保留下层直接调用语义。
- `011a05fa`：Shim 在发起 exec/update/stats RPC 前克隆 ttrpc client，不再持有共享 client
  mutex 跨越 RPC await。
- `d40d9e07`：所有 clone 共享 per-container operation gate；Start/Update 与 Sandbox
  Delete/Stop/Pause 使用统一 sandbox fence，Pod pause 按稳定顺序获取全部 container gate。
- `4066b17d`、`6662316e`：识别 systemd 已输出 `LoadState=not-found` 但退出码非零的收集
  结果，并在精确 leaf identity 已确认后对 `show` 收集竞态做最多 1 秒有界重读；不确定身份、
  populated leaf 和持续查询失败仍 fail-closed。
- `2dcf26b9`、`10b7af56`：有界等待后重新核对 parent/leaf identity，在检查 leaf 为空前后
  以及 `reset-failed` 前再次验证，拒绝把同路径上新建的 cgroup 当作原 owner；确定性测试保留
  旧 inode 后在原路径创建替代 leaf，覆盖 inactive/failed 分支且确认不会调用 reset。
- 最终 Shim SHA-256：
  `6a0c0cd316eac75663cdde7d45cb4e240ba50a121701344f1a6337338414469d`。
- 最终 Agent ext4 SHA-256：

## `K8S-OQ-017`：极端 memory downsize

首轮脚本 `inv-986kd00166` 失败是错误地要求 Kubernetes 路径必须出现 Agent
`checkBeforeUpdate` 事件。日志审计 `inv-a86ket058u` 证明 Kubernetes 1.36 kubelet会在 CRI
之前按当前使用量拒绝/延迟极端下调；Pod 没有 deadline wedge，namespace 自动清理。构建中的
定向测试同时证明直接 CRI 未携带该字段时，Shim 对 managed container 默认补为 true。

结论：关闭 `K8S-OQ-017`。Kubernetes owner 的写前检查留在 kubelet；Shim 为直接 CRI 提供
安全默认值；只有显式 false 的低层调用保留同步 reclaim 风险，不属于首版 Kubernetes 支持面。

## `K8S-OQ-022`：重启、resize 与长 exec

一次失败复现 `inv-b86kfmg42b` 及对应日志证明：旧 Shim 的共享
`Arc<Mutex<AgentServiceClient>>` 会被长 exec RPC 占用，导致 Update/Stats 无法进入 Agent。
`011a05fa` 解除该 client-handle 串行化后：

- `inv-086krx09qc`：创建受控测试 Pod；
- `inv-386ks905gb`：在线重启 containerd，Pod UID/sandbox/container/VM identity 不变；
- `inv-v86ksj0ndb`：无 exec resize 立即通过；带受控长 exec 的第二次 resize 在 1 秒内通过，
  Guest 数值精确、Pod identity 稳定、restart count=0、HTTP 正常，namespace 删除，exec
  按删除信号退出 143。

更激进的持续压力矩阵 `inv-086kus0i8w` 暴露剩余 Agent container-operation 串行化：第一次
Update 得到 ttrpc receive timeout，探针有 passfd/exec timeout；约 53 秒后 kubelet重试产生
`ResizeCompleted`，Pod spec/status/allocated 与 Guest 最终收敛。随后按标签删除 namespace，
压力命令随对象删除退出 137。该行为登记为首版已知限制，不把它描述成通过能力。

## ephemeral-storage 责任边界

- `inv-386mfegiev`：Cube Pod 的 Host-backed emptyDir 写入 96 MiB，Pod 的容器
  ephemeral-storage requests/limits 分别为 8/16 MiB；kubelet 将其标准驱逐为
  `phase=Failed reason=Evicted`，message 明确为 Pod ephemeral local storage usage 超过
  containers 总限额 16 MiB。
- 同时 Node `DiskPressure=False`，排除节点级磁盘压力驱逐；测试 namespace 正常删除。
- `inv-086mip0u7c`：W2 归零到 0 sandbox/VM/task-shim/CNI/active-lease/mount/reaper。

结论：关闭 `K8S-OQ-016`。Host-backed emptyDir 与 containerd 标准 snapshot 仍由 kubelet/
containerd 计量；Cube Guest 临时 rootfs upper 不回写 Host snapshot，首版不声明这部分写入可
被 ephemeral-storage 精确计量。

## 首版支持判定

| 场景 | 判定 |
|---|---|
| QoS、多容器、classic init、restartable sidecar、Pod-level resources | 支持 |
| Host VM 静态 CPU/memory/PIDs ceiling；Guest per-container CPU/memory/swap/PIDs/hugepage | 按 S3.4b/c 支持矩阵支持 |
| 普通 Kubernetes in-place resize；containerd 在线重启后 resize | 支持 |
| 默认规格下 workload Guest OOM | 支持，表现为 `OOMKilled/137` |
| 显式 VM memory 小于 256 MiB | 明确拒绝 |
| aggregate 超过创建时 VM capacity 的 resize | 二期，`K8S-OQ-018` |
| 有限 kubelet `podPidsLimit` 的跨 VM accounting | 未支持，`K8S-OQ-019` |
| 持续长 exec 与同容器 resize 并发 | 首版已知限制，`K8S-OQ-022`，S5.4 整改 |
| 12 Sandbox 创建 2 秒即同时取消的零告警 | 未支持；kubelet 可重试收敛，`K8S-OQ-023` 转 S5.4 |
