## 17 个失败的责任分类

### 当前 Cube 架构差异：16 项

1. `empty_dir.go` 12 项：memory-backed EmptyDir 的数据、权限、FSGroup、跨容器共享和清理
   正常，但 Host tmpfs 经 virtiofs 导入 Guest 后，容器 `statfs` 看到 FUSE magic，而非
   tmpfs。需要 Guest Pod 级 tmpfs，而不能伪造文件系统类型；见 `K8S-OQ-025`。
2. `mirror_pod_test.go:207` 1 项：修正 privileged 门禁后，NFS server 容器已启动，
   但 Host kubelet 挂载该 Guest 内导出的 virtiofs-backed EmptyDir 时，NFS server 返回
   `No such file or directory`。需要 Guest-local 可 export 的卷后端或专用块设备；见
   `K8S-OQ-035`。
3. `mount_rro_linux_test.go:130` 1 项：首版正确报告“不支持 recursive read-only”，拒绝
   recursive 请求的用例通过；但普通 read-only 路径要求保留嵌套 mount identity，当前
   virtiofs 导入后丢失该 identity。继续广告不支持，不伪装 capability；见 `K8S-OQ-034`。
4. `summary_test.go:461` 1 项：工作负载 I/O pressure 发生在 Guest cgroup，kubelet 查询的
   Host per-container PSI 没有该信号。需要 stats 聚合协议，而非伪造 Host cgroup；见
   `K8S-OQ-036`。
5. `cpu_manager_test.go:1909` 1 项：测试直接读取 Host
   `cri-containerd-<container>.scope/cpuset.cpus.effective`；Cube 的 Host 资源对象是 Pod VM，
   per-container cpuset 在 Guest。普通 CPU Manager/PodResources 映射用例已通过，只有这项
   Host 路径假设不成立；见 `K8S-OQ-036`。

### 挂接集群测试环境限制：1 项

`kubelet_server_tls_test.go:168` 的 client CA 热重载用例要求 runner 能改写并替换 kubelet
client CA，同时由现有 apiserver 重新建立信任。本 PoC 使用已运行的 kubeadm apiserver 和
临时 `kubelet-e2e.service`，`/configz` 最终超时；这是 runner/控制面耦合，不经过 Cube
Sandbox。应在 e2e_node 自管 control-plane 或专用 apiserver fixture 中重跑；见
`K8S-OQ-037`。

## 4 个 Skipped

1. recursive read-only capability 为 false，两个“runtime supports recursive read-only”分支
   按官方逻辑跳过；不支持分支的拒绝用例已通过。
2. `PodAndContainerStatsFromCRI=true` 时，官方 cadvisor container metrics 用例主动跳过；
   对应 CRI stats/summary/metrics 用例已执行。
3. SR-IOV PodResources 用例要求节点至少有一个 VF，本轮两台 PoC worker 没有 VF；其他
   Device/PodResources 用例 10/10 通过。硬件闭环见 `K8S-OQ-038`。

## 本轮关闭的真实缺陷

- Host CPU ID 到 Guest vCPU 的稳定映射、PodResources CPU/NUMA 返回、Pod/container stats、
  writable rootfs、hostname/FQDN、SIGKILL、sysctl、restartable sidecar 和 endpoint 网络均
  已通过官方用例。
- OCI Linux device 的容器目标路径不再错误限制在 `/dev`；Agent 使用一次 pin 住的 rootfs
  目录 FD、`openat`/`mknodat`/`fchownat` 和最终 FD bind，拒绝 `..` 与 symlink escape。
  设备类型位先过滤，再应用权限位；CDI `/tmp/CDI-Dev-2` 官方用例通过。
- CNI connected route 返回 `EEXIST` 时不再无条件忽略：必须精确回读 family、destination、
  source prefix、table、protocol、scope、type、OIF、gateway/via/multipath、onlink 与
  preferred source。特权 builder netns 的 IPv4 幂等、冲突和无副作用测试通过；builder
  以 `ipv6.disable=1` 启动，因此真实 IPv6 子项不适用，IPv6 identity 由纯逻辑测试覆盖。
