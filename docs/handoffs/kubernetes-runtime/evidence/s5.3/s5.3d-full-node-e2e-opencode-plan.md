## 信任边界

OpenCode 是执行者，不是裁判。它可以生成 shard、运行测试、诊断失败，并在自己的分支提交
候选修复；不得修改官方测试二进制、删除失败报告、把未执行项记为 Skip、把 runc/no-runtime
用例记为 Cube 通过，或自行编辑最终汇总。最终验收由独立 runner 重新执行并从原始制品生成。

如果允许同一个有 root 权限的代理同时控制测试节点、测试程序和证据文件，就不存在可靠的
“防作弊”证明。因此分两条路径：OpenCode 在诊断节点自由迭代；最终候选由 Codex 控制的验收
节点从冻结输入重新部署和执行。OpenCode 不能写验收 runner、预生成 inventory、最终聚合器或
验收证据前缀。

## 执行协议

1. 独立 runner 先用冻结二进制 dry-run 生成权威 inventory。基础环境预期 1197 个注册 spec；
   AppArmor 等条件可能注册 1201 个，差异必须由 profile manifest 解释，不能靠总数掩盖。
2. inventory 中每个 spec ID 预先分配到且只分配到一个 shard/profile。允许因 CPU Manager、
   Memory Manager、swap、AppArmor、SR-IOV 等采用不同节点配置，但 source commit 和运行时制品
   必须一致。
3. 每次运行前生成不可事后修改的 run manifest：run ID、基线 commit/tree、二进制和运行时
   SHA-256、节点/内核/containerd/kubelet 配置哈希、完整 focus/skip 参数、spec ID 列表和超时。
4. runner 同时保存进程退出码、stdout/stderr、Ginkgo JSON、JUnit、Kubernetes events、节点
   journal、CRI/containerd/Cube 日志以及前后资源基线；不能用 `|| true` 抹掉退出码。
5. 原始文件按 run ID 上传到不可覆盖的 COS key，上传后由验收端计算清单和 SHA-256。最终报告
   只能读取这些原始文件，OpenCode 生成的摘要仅作为诊断材料。
6. timeout/interrupted 只表示未完成；未执行 spec 回到队列，不得计为 Skip。retry 必须保留每次
   尝试，并在最终结果中暴露 flaky 次数。

## Cube 运行时归因

对每个创建 workload 的 spec 建立：

`spec ID -> namespace/Pod UID -> admitted runtimeClassName -> CRI runtime_handler -> containerd
sandbox/runtime -> CubeShim sandbox -> cube-vmm-worker Ready -> Guest container start`

最终按 spec 分类为 `CUBE_ONLY`、`MIXED`、`RUNC_ONLY`、`NO_RUNTIME` 或 `UNKNOWN`。显式
`test-handler`、host namespace、static/mirror Pod、helper Pod 和不创建工作负载的测试分别按
真实路径分类；`Passed` 不自动等于 `CUBE_ONLY`。任何有 workload 的 spec 出现 `UNKNOWN`，
对应 shard 的 Cube 验收无效。

## 修复与重跑规则

- OpenCode 发现缺陷后只在独立 clone 的候选分支提交，返回 commit、最小复现、失败责任层和
  受影响能力域；不得移动冻结 branch/tag。
- 候选修复先由 Codex review，再产生新的、带版本号的冻结基线和制品 SHA-256。不同 source 或
  artifact hash 的 Passed 不能合并为一份最终结果。
- 探索阶段可只重跑失败项；最终候选必须在同一 source/artifact 基线上重新覆盖全部适用 spec。
  profile 允许不同，但必须记录且可复现。
- 最终汇总后，由独立 runner 重跑全部 Failed/Skipped 和随机抽取至少 10% 的 Passed；结果不一致
  则撤回汇总并调查，而不是选择较好的一次。

## 验收标准

- 权威 inventory 中每个 spec 恰有一个最终状态：Passed、Failed、条件 Skip 或明确 Out-of-scope；
  没有缺失、重复、静默过滤和未解释的注册数差异。
- GPU、Windows、明确不支持的 host namespace 等可以 Out-of-scope，但必须逐项列名和理由；其余
  声明支持的 Linux/x86 Node E2E 必须实际执行。
- workload spec 的运行时归因 `UNKNOWN=0`；Cube 通过数只统计 `CUBE_ONLY`，`MIXED` 单列。
- 所有 Failed/Skip 有上游名称、首次原始报告、重跑结果、责任层、修复或不可支持理由。
- 最终基线前后 Sandbox、VM、worker、shim、TAP、mount、scope 和 active lease 回到 exact-zero，
  kubelet/containerd/CNI 与集群状态恢复。
- 独立聚合器和随机复验通过后，才能把 S5.3d 标记为 `DONE`；OpenCode 自报全绿不能作为证据。
